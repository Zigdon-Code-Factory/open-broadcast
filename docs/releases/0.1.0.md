# Open Broadcast 0.1.0

The first packaged release of Open Broadcast, a CPU-based microphone and webcam effects app.

## What's included

- DeepFilterNet3 streaming noise suppression and Silero voice activity detection through ONNX Runtime; no PyTorch runtime is required.
- Background blur, replacement and removal, plus face-tracked auto framing.
- A system-tray app with device selection, microphone level, video preview and persistent settings.
- Bundled, checksum-pinned models for offline operation after installation.
- Windows update checks and installer-based updates with SHA-256 verification, silent upgrade and relaunch. Updates require confirmation; automatic checks can be disabled.
- Audio regression tests and optional diagnostics for noise, speech, callback safety and virtual-cable routing.

## Getting started

1. Install the virtual microphone/camera drivers appropriate to your platform; these drivers are not bundled.
2. Select your physical microphone and virtual-microphone output in Open Broadcast, then start processing.
3. Select that virtual microphone in Discord, Zoom or another calling app. For VB-CABLE, Open Broadcast outputs to **CABLE Input** and the calling app uses **CABLE Output**.
4. Enable camera effects if desired and select the virtual camera in your calling app.

## Requirements and limitations

- Windows audio routing requires a virtual device such as VB-Audio Virtual Cable; macOS can use BlackHole. Virtual-camera output requires a compatible backend such as OBS Virtual Camera or Linux v4l2loopback.
- Windows binaries are not production-code-signed. The macOS app is ad-hoc signed, not Developer ID signed or notarized; operating-system security warnings may occur.
- Automatic installation of updates is supported only by the Windows installer build. Portable, macOS and Linux builds open the release page instead. Prereleases are not offered by the normal update check.
- Noise suppression, speech gating and auto framing depend on the source material and device configuration. Automated signal checks do not replace listening or real-call testing.
- Audio processing time does not include microphone, virtual-device or calling-app buffering; end-to-end latency depends on those components.

## Release verification

The release workflow runs the unit tests and frozen-app model/library smoke tests on each target platform before publication. Downloadable notes and packages from a manually dispatched workflow are test artifacts, not a published release. Source version `0.1.0` must match tag `v0.1.0` before publication is allowed.
